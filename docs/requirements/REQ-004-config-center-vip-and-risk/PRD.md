> 说明：本需求包同时覆盖 **VIP 规则** 与 **风控规则** 两个配置模块。两者复用同一套"市场模板 / 品牌覆盖 / 差异发布"的配置中心通用编辑框架，只在数据模型复杂度上不同：VIP 规则全部为标量字段；风控规则包含嵌套规则数组（`rules`）和例外列表数组（`exemptions`）。把它们放在同一个需求包内，是为了对齐配置发布框架；后续可按需要拆分为两个独立的开发包。

## 00. Brief

### 背景

商户后台需要一个能同时覆盖 VIP 规则、风控规则、优惠活动、渠道模板、支付策略、客服话术等多模块的统一配置中心。

当前两个原型（VIP、风控）已落地了配置中心的核心交互骨架：

- 同一个工作台支持「市场模板」和「指定品牌」两种作用范围。
- 编辑前展示原配置明细，编辑后展示差异并生成发布单。
- 复杂配置（数组类）支持「编辑匹配项 / 新增匹配项 / 不修改」，避免误替换整套规则。
- 单品牌商户自动退化为锁定态，与多品牌共用同一套前端。

继承自 [agent.md 第 6 节](../../../agent.md) 的配置体系原则：配置中心只保留两层数据模型——**市场模板**和**品牌覆盖**，不引入"品牌组模板"或"同市场品牌组继承层"。

### 目标用户 / 操作角色

- 商户运营：日常调整 VIP 等级、奖励金额、风控阈值等参数。
- 商户风控：调整风控规则包、评分规则、动作策略、例外名单。
- 商户管理员：审批高风险变更、复核发布单、操作回滚。
- 单品牌商户员工：仅操作唯一市场模板（锁定态）。

### 业务目标

- 一套前端复用于多品牌多市场、多品牌单一市场、单一品牌单一市场三类商户。
- 提交前必须能看到「作用对象 × 原值 × 提交后值 × 来源层级」，杜绝盲改。
- 数组类配置（风控规则、例外名单）按 ID / 匹配项增删，不再让"选择方案"覆盖整套规则。
- 跨币种金额字段不允许统一设置，强制按单市场分组编辑，避免 5,000 THB 被误写到 VND 品牌。
- 高风险动作（如临时冻结、提款阈值、规则包替换）必须可识别，强制复核后发布。

### 范围

In scope：
- VIP 规则模块：等级与晋级、奖励与返水、资金边界三组共 9 个字段（详见 §02 / §04）。
- 风控规则模块：规则包与评分、处置策略、例外名单三组共 6 个对象（详见 §02 / §04）。
- 共用框架：作用范围切换、场景阶梯、市场卡片、品牌选择、字段编辑、差异预览、发布单生成、变更摘要面板。
- 单品牌商户的锁定态降级。

Out of scope（本需求包不交付，但需对接）：
- 真实的版本记录列表（侧栏 `版本记录 42` 仅为入口占位）。
- 真实的回滚单流程（侧栏 `回滚单 3` 仅为入口占位）。
- 优惠活动、渠道模板、支付策略、客服话术、报表口径等其他配置模块。
- VIP 等级表本身的等级阶梯设计（如每级返水比例、累计有效投注门槛）；本期只交付方案选择（`轻量 6 级 / 标准 10 级 / 高价值 12 级`）。
- 灰度发布的实际灰度策略与流量分发实现（仅在 `publishMode` 中选择"灰度 10% 后全量"）。
- 审计日志的查询页与字段定义。
- 风控规则的实际命中和评分计算后端服务。

### 成功标准

- 多品牌多市场商户可以在不切换页面的情况下，按单市场模板维护一组币种敏感字段，提交后只影响该市场。
- 选中多币种品牌时，金额字段在 UI 上锁定，无法发起跨币种统一设置（验收点 AC-005）。
- 风控规则数组的「编辑匹配项」只修改命中规则 ID 的品牌，对没有该规则的品牌不偷偷新增（验收点 AC-008）。
- 单品牌商户进入页面后无法切换到「指定品牌」分段（验收点 AC-003）。
- 高风险变更提交时统计面板的「高风险动作」计数非零，并显示复核提示条（验收点 AC-006）。

### 已知约束

- 同一品牌生命周期只经营一个币种（agent.md 第 5 节）；金额字段必须随品牌币种走，不做汇率折算。
- 市场模板唯一键以国家为单位；币种和语言是市场模板属性（agent.md 第 5 节）。
- 平台默认模板不会自动覆盖已启用的商户市场模板。
- 平台端、商户端只做电脑版管理工作台，不做移动端。

## 01. Capability Spec

### 能力一句话定义

> 在商户后台为每个配置模块提供「先看原配置、再做变更、提交前生成发布单」的统一编辑发布能力，覆盖 VIP 规则与风控规则两个模块。

### 参与方

| 参与方 | 说明 | 是否直接操作 |
| --- | --- | --- |
| 商户运营 / 风控 | 在配置中心编辑字段、加入变更、发起发布 | 是 |
| 商户管理员 | 复核高风险发布单、操作回滚 | 是 |
| 平台运营 | 维护平台默认参数，作为新品牌的市场模板初始值来源；不直接操作商户配置 | 否 |
| 玩家 | 受 VIP / 风控规则影响（VIP 等级、提款额度、风控冻结），但不操作配置中心 | 否 |

### 使用场景

1. 多品牌多市场商户每日运营：选择 `市场模板` scope，逐个市场调整 VIP 返水周期或风控提款复核阈值，发布到该市场全部继承品牌。
2. 多品牌多市场商户的品牌覆盖：选择 `指定品牌` scope，对单一品牌做非标参数覆盖（例如 Metro 把"快进快出"规则评分从 35 降到 30）。
3. 多品牌单一市场商户：所有品牌币种相同，可在 `指定品牌` scope 下勾选多个品牌做批量金额覆盖。
4. 单一品牌商户：scope 锁定为 `市场模板`，品牌侧只读，只能编辑唯一市场模板。
5. 高风险变更复核：商户运营提交"替换为高敏感风控包"后，商户管理员在差异预览中确认 `状态=需复核` 的行并最终发布。

### 涉及端

- 平台端：本期不涉及前端改造；后续需要维护"平台默认参数"作为市场模板初始值来源。
- 商户端：本需求包的主交付物——配置中心电脑版工作台。
- 会员端：不涉及，但 VIP 等级、提款额度、风控冻结等结果会通过会员端呈现给玩家。
- 代理端：不涉及。

### 上游依赖

- 商户的市场模板配置（REQ-001 占位的"市场模板配置"需求）必须存在；本需求消费市场模板的国家 / 币种 / 语言 / 时区。
- 商户的品牌列表必须存在；每个品牌需有 `id / name / currency / status(live|test|pause)` 元数据。
- 平台默认参数（VIP 等级方案、风控规则包定义）必须能被商户继承为市场模板初始值。

### 下游影响

- 数据：写入两层存储——`市场模板配置`（按 currency 维度）和 `品牌配置覆盖`（按 brand 维度）；发布单作为审计基线。
- 权限：高风险动作（见 §05）必须触发"具备最高确认权限的角色复核"；普通字段沿用商户管理员权限。
- 报表：VIP 等级、返水周期、提款额度、风控冻结结果是结算、风控报表、客服处置的输入；变更生效时间会影响报表口径。
- 配置：发布生效方式（`人工复核后生效 / 立即生效 / 灰度 10% 后全量`）会决定其他模块的读取时机。
- 审计：每条发布单必须可追溯到操作人、品牌、字段、来源层级、原值、提交后值、状态。

### 状态流转（草稿 → 发布）

```text
[空草稿]
  └─ 加入变更 → [有草稿]
      ├─ 校验通过 + 选中作用对象 → 启用 [预览差异] 和 [发布] 按钮
      └─ 未选作用对象 → [校验阻断]（按钮禁用）
[有草稿]
  ├─ 切换 scope / 切换市场 / 切换品牌选择 → [空草稿]
  ├─ 点击「清空草稿」 → [空草稿]
  ├─ 点击「预览差异」 → 打开差异模态（不修改草稿）
  └─ 点击「确认发布」（差异模态内） → 写入市场模板或品牌覆盖 → [已发布] → Toast 反馈 → 草稿清空
```

### 异常和边界

- 单品牌商户进入页面：scope 强制 merchant，scope tab 的"指定品牌"按钮禁用并提示「单品牌商户只开放唯一市场模板配置」。
- 未选择任何品牌（scope=brands）：摘要面板「校验阻断」=1，发布按钮禁用；点击「校验」给出 toast "请先选择作用品牌"。
- 多币种共选 + 金额字段：字段卡片标记「按市场编辑」并禁用编辑按钮；点击按钮 toast 提示锁定原因。
- 「恢复市场模板」操作：编辑器内目标值即为当前活跃市场模板的默认值；发布后该字段从品牌覆盖回退到市场模板继承。
- 「不修改」操作：从 `state.edits` 移除该字段，不进入发布单。
- 差异模态在 scope=merchant 时按市场行展示（"泰国 / THB 市场模板"），在 scope=brands 时按品牌行展示。

### 历史数据处理

- 是否追溯：否。本需求只决定未来发布；不回填历史快照。
- 快照要求：每次发布生成一份发布单快照（含品牌、字段、原值、新值、来源层级、操作人、时间戳），作为审计与回滚依据。具体存储结构见 OPEN-204。

## 03. Flows

### 主流程：在多品牌多市场商户编辑 VIP 字段并发布

1. 进入「VIP 配置中心」页面，默认 scope=`市场模板`（也允许从 `指定品牌` 进入；以原型默认为准）。
2. 在"场景阶梯"中点击"1 多品牌多市场"或在市场卡片中点击目标市场（如 `泰国市场`），active market 切换。
3. 在工作台中找到目标字段，点击「编辑」展开编辑器。
4. 在原配置明细表格中确认每个市场或品牌的当前值与来源（继承 / 品牌覆盖）。
5. 选择操作方式（`统一设置 / 恢复市场模板 / 不修改`）→ 输入或选择目标值 → 点击「加入变更」。
6. 右侧摘要面板出现变更项；如为高风险字段，「高风险动作」计数 +1，复核提示条显示。
7. 点击「预览差异」打开差异模态，按行确认作用对象 × 原值 × 提交后值。
8. 点击「确认发布」：原型层面将草稿写入对应市场模板或品牌覆盖；Toast「发布单已生成」。
9. 摘要面板清空，进入下一轮草稿。

### 主流程：在风控规则模块编辑评分规则

1. 进入「风控配置中心」页面，按需要切换 scope 与作用对象（同上）。
2. 在「规则包与评分」分组找到「评分规则列表」，点击「编辑」。
3. 选择操作方式：
   - `直接编辑规则`：在下半段「编辑目标」下拉中选择已有规则 → 修改 condition / score / enabled → 「保存明细变更」。
   - `新增规则`：在上半段「规则」下拉中选择 `同设备短时批量注册` 或 `同银行卡多账号` → 「加入变更」。
   - `替换为高敏感包`：直接「加入变更」即可。
   - `不修改`：从草稿剔除。
4. 原配置明细表格的「若发布本对象」列实时显示每个品牌的发布后规则摘要。
5. 预览差异 → 确认发布，与 VIP 流程一致。

### 分支流程

- 切换市场卡片：弹出 toast「已选择 X 市场模板，本次只编辑该市场」，并清空 `state.edits`。
- 选择"全部运营中"预设：选中所有 `status === "live"` 的品牌。
- 选择"测试品牌"预设：选中所有 `status === "test"` 的品牌。
- 选择币种预设（THB / VND / PHP）：选中该币种且 `status !== "pause"` 的品牌。
- 清空预设：清空所有品牌选择。
- 切换"场景阶梯"中其他场景：触发 `applyScenarioPreset()`，重置 scope、selected、activeMarket。

### 失败流程

- 未选择任何作用品牌（scope=brands）：摘要面板「校验阻断」=1，「预览差异」与「发布」按钮禁用；点击「校验」给出 toast "请先选择作用品牌"。
- 选中多币种品牌后点击金额字段「编辑」：按钮显示「锁定」状态并禁用；点击会 toast 出锁定原因「当前选中 泰国 / THB / 越南 / VND，金额字段需按单一市场分组编辑」。
- 关闭差异模态：草稿保留，不发布。

### 结束状态

- 发布成功：草稿清空，工作台重新渲染，市场模板或品牌覆盖已更新，Toast 反馈。
- 用户离开页面：原型层未保存草稿；生产实现是否需要后端草稿保存见 OPEN-203。

### 状态

- 空状态（变更列表）：「尚未产生变更」。
- 加载状态：原型未演示；生产实现需要补充骨架屏（OPEN-205）。
- 禁用状态：单品牌商户的 scope tab；多币种下的金额字段编辑按钮；草稿为空时的预览/发布按钮。
- 错误状态：未选品牌时统计的「校验阻断」=1；当前未演示字段级错误（如数字越界）。
- 无权限状态：本期由商户角色矩阵控制，详见 §05。

### 批量操作

- 是否支持：是。
- 作用范围：scope=brands + 多品牌选择时，标量字段（非币种敏感）可一次性写入多个选中品牌；金额字段强制按单市场分组，不允许跨币种批量。
- 提交前预览：通过差异模态展示每个品牌的来源层级、原值、发布后值；状态列区分「可发布 / 需复核」。

| 发布单 | 商户 | 商户 + 操作人 | **是**（审计） |
| 评分规则的 `rules` 数组明细 | 品牌覆盖 或 市场模板 | 跟随宿主层级 | 是 |
| 例外名单 `exemptions` 数组 | 品牌覆盖 或 市场模板 | 跟随宿主层级 | 是 |
| 草稿（state.edits） | 用户会话 | 仅前端 | 否（原型未演示后端草稿；见 OPEN-203） |

### 权限

| 动作 | 角色要求 | 数据范围 | 审计要求 |
| --- | --- | --- | --- |
| 查看 VIP / 风控配置 | 商户员工：运营 / 风控 / 管理员 | 仅本商户 | 是（读日志） |
| 编辑非高风险字段 | 商户运营 / 风控 / 管理员 | 本商户 | 写日志，记录用户 ID、字段、原值、新值 |
| 编辑高风险字段 | 商户管理员（或最高确认权限角色） | 本商户 | 写日志 + 复核标记 |
| 发布到市场模板 | 商户管理员 | 本商户全部市场 | 复核 + 通知 |
| 发布到品牌覆盖（含高风险） | 商户管理员 | 选中品牌 | 复核 + 通知 |
| 回滚 | 商户管理员 | 单条发布单 | 写日志（本期不交付，见 OPEN-202） |
| 查看版本记录 | 商户员工（只读） | 本商户 | — |

补充：原型未演示角色名与角色矩阵的具体定义，统一称"商户管理员 / 商户运营 / 商户风控"。实际角色映射见 OPEN-201。

### 报表口径

- VIP 等级方案 / 晋级口径切换会改变报表的等级分布与晋级转化率；变更生效日必须能在报表中标记。
- 风控规则评分变更会影响命中率、人工复核单数、临时冻结数；同样需要在报表中标记生效日期。
- 币种敏感字段的金额变更必须以「品牌币种」为单位呈现，不做汇率折算（agent.md 第 5 节）。
- 报表口径具体字段定义不在本需求包内，统一记录到 OPEN-206。

## 06. Acceptance

### 功能验收

- **AC-001**：在多品牌多市场商户中，进入 VIP 配置中心后默认能看到 Scope 分段、场景阶梯（3 步）、市场卡片、品牌带、3 个分组共 9 个字段、摘要面板。
- **AC-002**：进入风控配置中心后能看到上述结构，且分组改为 3 组共 6 个对象（含 1 个 rules 数组、1 个 list 数组）。
- **AC-003**：单品牌商户进入页面：scope tab「指定品牌」呈禁用态；品牌带显示锁定提示「单品牌商户已锁定为唯一市场模板，品牌侧只读继承」。
- **AC-004**：摘要面板的「影响对象」「修改字段」「高风险动作」「校验阻断」四项数据与当前 scope + selected + edits 状态实时一致。

### 规则验收

- **AC-005**：当 scope=brands 且选中品牌跨币种（如同时含 THB 和 VND）时，所有 `currencySensitive: true` 字段（VIP：`birthdayBonus`、`withdrawLimit`；风控：`withdrawReview`）的编辑按钮显示「锁定」并禁用；点击会 toast 出锁定原因。
- **AC-006**：发布单的差异表中，所有 `risk: true` 字段的「状态」列显示「需复核」；摘要面板的「高风险动作」计数与之一致；高风险提示条（橙色横幅）必须显示。
- **AC-007**：「恢复市场模板」模式发布后，对应品牌的字段值变更为该品牌币种对应的市场模板默认值（`templateValue(field, brand)`）。
- **AC-008**：「直接编辑规则」模式发布后，仅修改各品牌规则数组中匹配 `targetRuleId` 的条目；对该规则不存在的品牌（如 Nova 删除了 `ip-jump`），其规则数组保持原样，不会被偷偷新增。
- **AC-009**：「新增规则」模式发布后，若品牌规则数组已包含同 id，跳过；否则在数组末尾追加；不会改变其他规则的顺序与值。
- **AC-010**：「替换为高敏感包」模式发布后，品牌规则数组被替换为「四条基础规则 + 同银行卡多账号」共 5 条。
- **AC-011**：「新增例外」发布后，若数组已包含该字符串则跳过；否则追加；「移除例外」仅按字面匹配 `测试账号免冻结`。
- **AC-012**：差异预览模态行内信息包括：品牌 / 币种 / 字段（对象）/ 来源层级 / 当前值 / 发布后 / 状态七列。

### 权限验收

- **AC-013**：商户运营对高风险字段的「编辑」按钮可见，但「发布」按钮的差异行 `状态=需复核` 行无法直接提交（最终落地由 OPEN-201 决定）。
- **AC-014**：发布日志能查询到操作人、品牌、字段、来源层级、原值、新值、时间戳。

### 异常验收

- **AC-015**：scope=brands 时清空所有品牌选择，「校验阻断」=1，「预览差异」与「发布」按钮禁用。
- **AC-016**：切换 scope / 切换市场 / 切换品牌选择会清空 `state.edits`；切换前若存在草稿，需弹出确认（确认行为未在原型演示，见 OPEN-207）。
- **AC-017**：单品牌商户点击 scope tab「指定品牌」时 toast 提示「单品牌商户只开放唯一市场模板配置」。
