③ 阶段详解

0需求大纲

输入业务想法 / docs/migration-diff-list.md 待迁移项 / 源盘点（docs/migration/〔规划中〕，源站 = Ar_V1_Admin .NET 旧后台）
动作一句话能力定义 + 范围（In/Out）+ 分流判断
门控：能力定义 + 范围清晰 → 进阶段 1

1需求归档（先归档再做原型）

REQ建 docs/requirements/REQ-xxx-name/ 多文件包（00-brief→…→99-change-log，按规范 §4）
MIG填 docs/templates/migration-page-template.md 单页对照，通用交互引用 saas-phase2-feature-spec §二
纪律已拍板规则 / OPEN-xxx 未决 / 临时假设 三类分清，不藏规则于原型
门控：达 Approved for Prototype 最低要求

2原型

动作建 prototypes/REQ-xxx-name.html，遵循 prototype-design-spec.md（token/控件/交互/层级）
MIG多复用现有页与通用交互规范，可不单独建原型
门控：原型可表达核心交互

3评审

动作按规范 §8 评审 6 问（目标→范围→规则冲突→数据权限→交互服务规则→验收可测）+ Ready 检查
门控：所有 Blocks-Development 的 OPEN 关闭，无"开发时再定" → Approved for Development

4开发实现 · Ar_V3_LottoPlatformDesign

新功能superpowers 链路：brainstorming → planning → TDD → code-review
迁移页list-page skill + 字段对齐 §5.3 + newMark.ts 标「新」
红线本地 mock · 无真实 HTTP · pnpm build 必过
产出代码 + 誊写 docs/migration-changes.md

5验收

动作逐条点验 06-acceptance / MIG 的 AC；跑 typecheck + lint + lint:i18n + build
门控：验收全过 + build 绿 → Accepted

6最终呈现

原型发布 GitHub Pages（eason200116/saas-desigh）
V3演示页面 / 截图交付
收尾99-change-log / migration-changes 记录变更与决策人

  3. 同一概念只在一处定义，其他地方引用（规范 §9）。
  4. 未拍板的写 OPEN-xxx，不写成确定语气。
