4 · AI 基本规则

摘自 agent.md 与 标准工作流，适用于本仓库所有产品梳理 / 文档 / 原型 / 开发协作。

① 先读上下文

动手前先读 README / handoff / 标准规范 / 关联需求包；已拍板原则优先级高于临时推测。

② 需求先归档，再做原型

新增需求先建/更新需求包（背景·目标·范围·规则·流程·权限·验收）；原型只表达交互，业务规则不藏在 HTML 里。

③ 区分三类内容

已拍板规则 / 待确认问题（标阻塞级别）/ 临时假设，三者分开，不混在一个文档。

④ 维护主骨架

聚焦 SaaS 包网主骨架（平台/商户/品牌/市场模板/域名/渠道/玩家/代理关系/团队权限/四端入口/配置继承），其余功能挂在骨架下、不另起层级。

⑤ 遵守已拍板产品原则

商户=合同/计费/团队边界；品牌=玩家/钱包/订单/风控/渠道隔离边界；一品牌一币种、不混加不折算；市场模板以国家为唯一键；域名属品牌、渠道只绑同品牌域名；来源归因/代理关系/业绩归集三者分离；不提供转代。调整须先写原因/影响/替代规则并待确认。

⑥ 配置体系两层模型

仅「市场模板 + 品牌覆盖」两层，不增「品牌组模板/继承层」；同市场品牌组配置=批量写入品牌覆盖；跨市场只展示切换、不同时写多个市场模板。

⑦ 前端与原型原则

平台/商户端只做电脑版工作台；设计顺序 多品牌多市场 → 多品牌单市场 → 单品牌单市场，复用同一套前端；原型先看原配置再变更，提交前展示作用对象/原值/新值/来源层级/差异；数组配置支持增改移、避免整套误替换。

⑧ 文件组织

docs/product（长期上下文）· docs/requirements（编号需求包）· docs/standards（规范）· docs/templates（模板）· prototypes（HTML 原型）；不在根目录堆临时文档。

5 · 我的规则（协作约定 / 偏好）

用户对协作方式的既定要求，与上述 AI 规则并列遵守。

迁移：适配而非照搬

功能迁移与新功能一律遵循 V3 现有约定，绝不逐字照搬参考站（SitINR）。

这类编辑一律页内完成、不弹窗

行编辑 / 字段编辑 / 配置全站页内完成；存量 *FormModal 逐步改页内；动非归属模块前先确认。

迁移新增项挂可移除「新」标

新增列/功能用可一键去除的「新」徽标标记，便于区分、收尾批量去除。

原型为中文版、i18n 无原文键

交付前自查无 i18n 原文键乱码。

不开浏览器盲调，先看代码

卡死/白屏等优先看代码（字典缺项 / hook override / 响应式写法），不开浏览器调试能从代码看出的问题。

交付前自测再呈现

完成后先自测（build + 渲染路径推演）确认，再展示给用户。

模块归属边界

负责 报表 / 风控 / 系统 / 财务 / 游戏管理 5 个一级模块；改 会员 / 运营 / 配置 等其它模块前先确认。

新功能走规范链路、维护性改动走常规流程

新增页面/模块/hook 走 brainstorming→planning→实现→review；改 bug/字段对齐/补 mock/文案走常规流程。
