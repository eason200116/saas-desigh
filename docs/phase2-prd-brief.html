📘 二阶段产品需求文档（PRD）· 需求目的与框架

范围：会员相关功能迁移 + 升级 · 配套文档：交互介绍 / 新增字段介绍 / 验收口径
一句话：把旧后台（SitINR）里会员相关的功能搬进新 SaaS 后台并顺手升级——共 22 个功能页、一套新导航框架、一套「会员从哪儿来」的归因体系、一条广告投放配置链。交付以 3100 可点击原型为准（真实交互、非占位）。
本文只讲「为什么做、做什么框架」；逐页交互见《交互介绍》、字段见《新增字段介绍》。

一、需求目的

维度说明
背景旧超管（SitINR · .NET）会员相关能力分散、归类混乱；新 SaaS 多商户后台需承接这批能力并按多商户/多市场重构。
核心目的① 补全会员相关功能（对照源站逐页迁移）；② 重新归类（风控/配置中心从会员子项提升为一级模块）；③ 升级（会员从哪来的「归因体系」+ 会员列表/详情增强）；④ 打通推广分发获客链路前半段。
价值运营可在一个后台完成会员查询/分组/风控/返佣/推广配置；归因体系让"拉新成本与渠道效果"可溯可算。
不在本期活动营销整块（转盘/邀请/签到/积分商城）、代理关系树导入、游戏管理全线、财务大部分、多维报表、KW/CPF/实名认证、底层系统配置。

二、本期交付框架（5 大块）

#交付项框架说明
①会员管理深度迁移按源站对照补全会员相关功能并按分类重新归属，共 22 个已建功能页（分布见第三节）。
②顶部导航分类优化8 大主 Tab 多列分组下拉（mega menu）；「风控管理」「配置中心」从会员子项提升为一级模块；菜单项带 新 / 原 / 移 角标。
③多标签页签栏功能页以页签多开并存、切换、关闭。
④会员详情归因 + 会员列表增强会员详情按指定位置注入红字归因字段（归因来源/代理数据/注册·登录设备）；会员列表同步红色新列 +「领取返佣 / 对上级返佣」行内开关。
⑤推广分发配置开放 渠道管理 / 域名管理 / 防封救援 / 解析检测记录，覆盖「域名 → 渠道 → 推广 → 获客归因」闭环前半段。

页面类型定义

22 个功能页按交互形态归为 5 类；同类页共用同一套骨架与规范（详见《交互介绍》通用骨架）。

类型定义 / 特征代表页面
查询列表页筛选区 + 表格 + 分页 + 行操作（增删改查 / 批量 / 状态开关）；最常见。分组管理 · 登录日志 · 短信验证码 · 站内消息 · 公告 · 渠道管理 · 域名管理 · 防封救援 · 解析检测 · 会员返佣等级 · 代理审核 · VIP操作日志 · 异常会员 · IP黑名单
配置页选商户 / 市场 → 行内编辑（不弹窗） → 保存 → 发布（未配置 / 有未发布修改 / 已发布 三态）+ 复制到其他商户；保存校验不通过标红 + 错误面板。VIP配置 · 返佣配置
报表 / 数据页只读统计；纯查询页无行操作，报表页可导出 / 切统计周期（真实刷新）。代理报表 · 昨日返佣等级 · VIP升级奖励记录 · VIP人数

详情页单页滚动多面板；字段按位置注入、行内编辑、数值可下钻风控。会员详情（基本信息 / 注册归因 / 数据统计 / 代理 / 登录 等面板）

四、归因体系框架（本期升级核心）

解决「这个会员从哪儿来」：注册时按优先级判定首个命中的来源并固化不再变更，详情页以红字字段呈现完整链路。
环节说明
判定优先级① 广告投放 › ② 邀请来源 › ③ 官方直推 › ④ 自然流量
五步固化进入 → 采集（埋点）→ 判定（按优先级）→ 固化（写档案）→ 展示（详情红字）
覆盖5 大归因类型 × 多种进入路径的枚举矩阵
联动会员详情所有「同IP / 同设备 / 同指纹」数值可点击，下钻「风控 · 同IP/设备检测」对应维度页签并带入该会员。

五、通用规范框架

  • 真实交互非占位：导出真实下载 CSV、搜索真实过滤、排序真实重排、表单保存真实回写、删除真实移除、翻日真实切数据，每步配 Toast。
  • 反馈完整：每个操作必有 Toast 或弹窗反馈；危险与批量操作必有二次确认。
  • 入口完整：每个已开放功能页可从顶部菜单进入，菜单带 新/原/移 角标。
  • 控件统一：全部列表页遵循同一套骨架（筛选 / 表格 / 工具栏 / 弹窗）；这类字段/行内编辑页内完成、不弹窗。
  • 多商户/多市场：顶栏切商户即按该商户数据重渲染；配置类按商户独立、可复制模板。
