推广分发配置说明
把 域名管理 → 打包管理 → 渠道配置 → 埋点管理 串成主配置链（PWA 管理 / 仿应用商店为可选增强）；支持 安卓 / iOS / 安卓壳包 / iOS壳包 / H5链接 / PWA 6 种分发形态。
一、推广配置标准工作流（SOP）
从「准备域名」到「上线跑量」的端到端作业流程，每阶段标注 负责角色 / 操作步骤 / 验收检查点 / 交付产出，按此清单逐步执行。
角色：运营 / 产品技术 / 研发广告优化师
1
🌐 域名准备运营 / 产品技术 / 研发 （域名管理）
  1. 申请并解析 主域名 + 推广域名
  2. 推广域名配 跳转域名 / 落地指向 / SEO
  3. 配置 防封谷歌页 / 苹果页 + 防封救援
✅ 检查点：域名解析生效、推广 URL 可访问、防封救援弹窗测试通过
📤 产出：可访问的推广 URL
2
📦 物料打包 / PWA技术 / 研发运营 / 产品 （打包管理 / PWA 管理 / 仿应用商店）
  1. 确定分发形态（安卓 / iOS / 壳包 / H5 / PWA）
  2. 原生 / 壳包：新增渠道包，上传安装包，渠道码写入
  3. PWA：走 PWA 管理 → 域名(内外链) → 页面配置 → 推送配置 → 发布
  4. 原生包按需配 仿谷歌 / 仿苹果商店；H5 / PWA 无需打包
✅ 检查点：包可安装 / PWA 可添加到主屏、渠道码正确、页面与推送配置生效
📤 产出：带渠道码的安装包 / PWA / H5
3
🔗 渠道绑定运营 / 产品 （渠道配置）
  1. 新建渠道，绑定落地指向（域名 / 包 / PWA / 商店页）
  2. 关联埋点（选定投放平台）
  3. 生成带渠道码的推广链接
✅ 检查点：链接可正常打开、渠道码随链接携带、归因来源写入测试通过
📤 产出：可投放的带渠道码链接
4
📊 埋点回传技术 / 研发广告优化师 （埋点管理）
  1. 对照「投放渠道 × 可投放端」确认平台与端
  2. 配置 Click 上报（像素）+ API 回传（CAPI / S2S）
  3. 配置必传基础事件：激活 / 注册 / 登录 / 首充 / 付费
  4. 填入 Pixel ID / Token（参考各渠道开发文档）
✅ 检查点：测试回传成功、事件到达广告平台、clickid 参数匹配
📤 产出：广告平台回传闭环
5
🚀 投放监控广告优化师 （报表管理 / 渠道数据）
  1. 广告平台建广告，填入推广链接
  2. 开始投放，实时监控回传数据
  3. 查看渠道 ROI 报表与会员归因来源
  4. 按数据 放量 / 降本 优化
✅ 检查点：转化数据回流、会员归因正确、渠道 ROI 可见
📤 产出：持续跑量与优化闭环
📋 使用方式：把 5 个阶段当作上线 Checklist，每阶段检查点全部 ✅ 后再进入下一阶段；任一检查点不通过则回退修复，避免链路断点导致投放无归因 / 无法跑量。

四、各形态配置流程（按顺序执行）
🤖 安卓 APK（原生安装包）
  1. 域名管理：配置主域名 + 推广域名（解析生效）
  2. 打包管理：新增渠道包 → 上传 安卓包(.apk)，渠道码写入安装包
  3. 仿应用商店：配置仿谷歌商店（可上架谷歌马甲包）
  4. 渠道配置：建渠道 → 落地指向 → 关联埋点 → 生成带渠道码链接
  5. 埋点管理：配置安卓回传（GAID；Facebook / TikTok / Kwai 的 click 或 API）
🍎 iOS（原生 / 保存桌面 / 苹果商店）
  1. 域名管理：主域名 + 推广域名
  2. 打包管理：新增渠道包 → 上传 iOS包(.ipa)
  3. 仿应用商店：配置仿苹果商店
  4. 渠道配置：渠道 + 落地指向，苹果安装类型（保存桌面 / 苹果商店）
  5. 埋点管理：iOS 回传（IDFA / IDFV，注意 ATT 授权）
📦 安卓壳包（WebView 套壳）
  1. 域名管理：配置推广域名（壳包打开的 URL）
  2. 打包管理：新增渠道包 → 上传 安卓壳包（渠道码写入壳）
  3. 渠道配置：渠道码写入壳包，装完即归因
  4. 埋点管理：壳内 H5 像素 + 服务端回传
📦 iOS 壳包（WebView 套壳）
  1. 域名管理：推广域名（壳访问 URL）
  2. 打包管理：新增渠道包 → 上传 iOS壳包
  3. 仿应用商店：苹果商店上架（已封装域名）
  4. 渠道配置：渠道码写入壳
  5. 埋点管理：壳内 H5 像素 + 回传
🌐 H5 链接（不下载，浏览器直开）
  1. 域名管理：推广域名 + 防封页域名（被封自动救援）
  2. 渠道配置：生成带渠道ID 的 H5 推广链接
  3. 埋点管理：H5 像素（FB / TikTok pixel）+ CAPI 服务端回传
  4. 安装引导：H5 顶部下载提示 / 弹窗，引导升级 PWA / APK（可选）
📲 PWA（可安装 Web App · 免下载 · 可推送）
  1. 域名管理：推广域名（内外链 / 语言切换）
  2. PWA 管理：页面配置 → 推送配置 → 发布
  3. 渠道配置：生成带渠道ID 的 PWA 链接
  4. 埋点管理：H5 像素 + CAPI 回传，结合推送召回
  5. 数据：域名统计看 打开次数 / 打开人数 / 下载次数

六、回传广告平台逻辑
每个渠道两条回传通道（Click + API），用点击参数把转化事件回传广告平台，闭环优化投放。
📍 Click 上报（前端像素）：落地页 / 壳内 H5 加载平台像素，记录点击参数（fbclid 等）后前端上报事件。简单，但受 iOS ATT、浏览器隐私、清缓存影响，丢包率高。
🛰️ API 回传（服务端 CAPI / S2S）：后台用点击参数 + 转化事件，服务端直连广告平台 API 回传。绕过浏览器限制，准确稳定，是 iOS 与高价值事件回传的命脉。
⚙️ 实战：两者并行（按 event_id 去重）——Click 保覆盖、API 保准确，iOS 尤其依赖 API 回传。

🔗 回传归因链路：
广告点击(带 clickid) → 落地 / 安装(渠道码 + clickid 写入会员归因) → 转化(注册 / 首充 / 付费) → 用 clickid 回传对应平台 → 平台优化投放(放量 / 降本)
说明：
· 壳包=WebView 套壳，把推广域名 H5 装进原生外壳，渠道码写入安装包，装完即归因，更新内容无需重新发版。
· PWA=可安装的渐进式 Web App（添加到主屏 / 离线 / 推送召回），免上架商店、免下载 APK；由 PWA 管理（域名内外链 / 页面配置 / 推送配置 / 发布 + 域名统计：打开次数·打开人数·下载次数）负责。
· H5链接无需打包，靠推广域名 + 防封页对抗封锁；像素/CAPI 回传是广告跑量与 iOS ATT 归因的命脉。
· 6 种形态最终都通过渠道码 + 埋点把来源写入会员「归因来源」，闭环到渠道 ROI。
