配置弹窗 · 商户作用域审计

盘点目标后台(member-app / localhost:8200)全部配置弹窗(新增 / 编辑),判断每个配置项应按单商户归属、还是支持多商户关联/下发,并标出当前缺口。架构前提:集团 → 市场 → 商户,顶部有全局「商户」切换器,商户是数据隔离边界。

~24个配置弹窗
2已具多商户(支代付/银行字典)
15+注入弹窗无商户字段
3类缺口
一句话结论:现状是「顶部全局切商户 + 配置弹窗大多不带商户字段」——对单商户操作员够用;但作为多商户 SaaS,有 3 类缺口需补商户作用域:① 个别配置天然应多商户关联/下发;② 集团/市场级操作员建配置时弹窗内无法指定目标商户;③ 系统用户(操作员)缺「可管辖商户」授权维度。
作用域:多商户 一份配置关联/下发多个商户(模态需多选) · 单商户 配置属某一商户(模态需单选 / 跟随全局) · 平台级 全集团统一、无商户维度。 当前:✅ 有 / ⚠ 部分/隐式 / ✘ 缺字段

③ 会员规则 / 风控 / 配置中心弹窗

配置弹窗应有作用域当前说明 / 建议
VIP配置多商户✘ 无字段模板型:常希望「一套等级模板下发多个商户」。建议支持「适用商户(多选)」或「保存为模板→批量套用」。

IP黑名单单商户✘ 无字段会员风控,per 商户;弹窗补单选商户。

④ 系统管理弹窗

配置弹窗应有作用域当前说明 / 建议
系统用户(操作员)
新增 / 编辑用户		多商户✘ 缺维度关键缺口:多租户下操作员需「可管辖商户」授权(一个操作员可管 1 个或多个商户 / 整个市场)。建议补「可管辖商户(多选 / 按市场授权 / 全集团)」。
系统角色(RBAC)平台级✅ 合理角色 = 平台级权限模板,无需商户维度(商户隔离靠「可管辖商户」在用户层做)。
IP白名单(后台登录)平台级✅ 合理后台访问控制,集团/平台级,无需按商户。

⚠ 三类缺口 · 优先级建议

缺口 A(高)· 多商户下发能力缺失:站内/公告消息、VIP等级、返佣等级 等模板型/群发型配置应支持「下发多个商户(多选, 可按市场 / 全集团)」;银行字典的「同步商户」宜并入新增/编辑弹窗。否则集团运营只能逐商户重复配置。
缺口 B(中)· 集团/市场级操作员无法在弹窗指定目标商户:15+ 注入式配置弹窗无「商户」字段,只能先切全局商户再建。建议统一补「所属商户」单选(默认=当前全局商户,可改);单商户操作员该字段可锁定/隐藏。
缺口 C(高)· 系统用户缺「可管辖商户」授权:这是多租户隔离的核心。操作员账号需绑定其可管辖的商户范围(单 / 多 / 按市场 / 全集团),否则全局商户切换器的可见范围无从约束。
口径来源:目标后台 localhost:8200 注入表单代码审计(域名/渠道/埋点/PWA/轮播/分组/IP/消息等弹窗均无商户字段)+ 原生 SIT 配置页(支代付三方=关联商户多选、银行字典=同步商户)。对照基准见 SIT 结构图谱。
