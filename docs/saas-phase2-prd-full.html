1 · 背景与目标

1.1 背景

旧后台 SitINR（.NET 单体）沉淀了完整的会员运营能力，但功能高度集中在「巨型」控制器中、缺乏多商户隔离，难以直接支撑平台的 SaaS 化运营。本期在将这些能力按新分类体系深度迁移至 V3 多商户后台的同时，统一交互骨架、补齐商户级数据隔离，并新增两项关键能力：一是回答「会员从哪儿来」的归因体系，二是打通广告投放获客的推广分发配置。

1.2 目标

  • 迁移补全：对照 SitINR 补齐会员相关功能并按新分类重新归属，本期落地 22 个功能页。
  • 导航重组：8 大主 Tab 改为多列分组下拉（mega menu），并将「风控管理」「配置中心」由会员子项提升为一级模块。
  • 归因可溯：注册即按优先级判定来源并一次性固化，会员详情以红字字段完整呈现获客链路。
  • 获客闭环：通过推广分发配置打通「域名 → 渠道 → 推广 → 获客归因」闭环的前半段。
  • 体验一致：全部列表页复用同一套筛选 / 表格 / 工具栏 / 弹窗骨架，并贯彻多商户隔离。

1.3 五大交付物

① 会员管理深度迁移（22 页） ·  ② 顶部导航分类优化（mega menu） ·  ③ 多标签页签栏 ·  ④ 会员详情归因字段 + 会员列表增强 ·  ⑤ 推广分发配置（渠道/域名/防封救援/解析检测）

3 · 角色与多商户模型

数据以「集团 → 市场 → 商户」三层组织，所有功能在商户维度上严格隔离。现阶段仅设一个「商户」角色（不细分子角色 / 权限分级），但后台支持跨商户的查询与配置——通过顶栏商户切换、筛选区商户下拉与按商户独立配置实现。本节定义这套统一规则，作为后续各功能页的共同前提。

现阶段角色口径：仅一个商户角色，登录后即以该角色操作；不区分运营 / 风控 / 配置等子角色。多商户能力体现在数据与配置维度（可查多商户、按商户配置），而非角色维度。
  • 多商户结构：集团 → 市场 → 商户 三层视角。顶栏切换商户后，所有列表页按该商户数据自动隔离重渲染。
  • 多商户查询：所有查询页筛选区「商户」下拉恒在首位，选项 =「所有商户」+ 各商户，默认 = 顶栏当前商户；可选「所有商户」做跨商户查询。
  • 商户列：列表首列展示「商户」蓝色 pill；单一商户视角下自动隐藏该列。
  • 多商户配置：VIP 配置 / 返佣配置等按商户独立配置，支持「选商户 → 保存 → 发布」+ 复制模板到其他商户，实现一处配置、多商户复用。

5 · 归因体系（核心）

归因体系回答「这个会员从哪儿来」，是本期最核心的新增能力。其结果在注册时一次性判定并固化，贯穿会员详情展示、代理归属与风控下钻。

5.1 判定规则（优先级）

① 广告投放› ② 邀请来源› ③ 官方直推› ④ 自然流量

会员注册时，系统按上述优先级自上而下匹配，命中的第一个来源即为「主归因」，写入会员档案后 固化不再变更。四类来源的判定依据与代理关系如下：

归因类型判定依据（命中标识）是否产生代理关系
① 广告投放带广告点击 ID（如 fbclid）或 UTM 参数；含官方链接 + 广告标识、广告 + 邀请码（裂变）等子情况。仅「裂变获客」子情况有，余无。
② 邀请来源携带有效邀请码：个人邀请码（手填）、转盘活动码、任务活动码，及活动码过期降级为正常邀请。有（绑上级 / 一级代理，可后台划转）。
③ 官方直推仅带官方推广链接标识、无广告标识、无邀请码。无。
④ 自然流量无任何投放/邀请标识：搜索引擎进入、站外 Referrer、直接访问、参数解析失败兜底、仅无效邀请码等。无。

上述四类共细分 18 种穷举情况，每种的「来源 → 入口 → 注册 → 采集 → 留存」完整脉络见 §4.6 归因穷举矩阵 ↗。

5.2 判定流程（5 步固化）

① 进入→ ② 采集→ ③ 判定→ ④ 固化→ ⑤ 留存
步骤说明
① 进入会员通过某域名 + 渠道链接进入站点（广告落地页 / 官方渠道 / 站外链接 / 直接访问）。
② 采集埋点采集基础事件（激活/注册/登录/首充/付费）与进入参数（点击 ID、UTM、Referrer、邀请码、设备/IP/指纹/包名）。
③ 判定按 §5.1 优先级匹配首个命中来源，确定主归因、注册渠道、平台/搜索引擎、邀请码与邀请类型。
④ 固化将判定结果写入会员档案：主归因 / 注册渠道 / 注册时间 / 设备·IP 固定不变；代理关系（上级/一级）可后台划转。
⑤ 留存会员详情以红字字段呈现完整链路，可点可复制；同 IP/设备/指纹数值可下钻风控页。

5.3 归因字段（27 红字，3 组）

会员详情按指定位置注入下列新增字段，布局不变、以红字标识、可点可复制。

字段定义

邀请码注册实际使用的邀请码，关联邀请人 / 代理。
邀请类型正常邀请 / 转盘活动邀请 / 邀请任务。
邀请人邀请码发起人 ID，通常＝直接上级代理，可点击下钻。
访问客户端最近一次访问的客户端：pc / h5 / 安卓 / ios / 壳包。

6.3 风控管理

  • 人数蓝链下钻会员列表并自动按该 IP/设备查询。

6.4 配置中心

REQ-CFG-01VIP 配置源 VipLevel + VipCurrencyExp
  • 双页签：VIP 等级（VIP0–VIP10 固定 11 级，行内编辑无弹窗、去 ID 列、名称只读）+ 经验值配置（按币种换算）。
  • 顶部商户工作区（选商户→保存→发布）+ 复制模板到其他商户；保存校验标红+错误面板；ⓘ 配置介绍。
验收：等级固定不可增删；等级/经验逐级递增、数值≥0。
REQ-CFG-02返佣配置源 RebateLevel + RebateLvRateConfig
  • 双页签：返佣等级管理（晋升条件表，0 级基础不可删）+ 返佣费率配置（一~六级 × 五游戏）。
验收：同级五大类费率之和 >4% 校验拦截（标红+错误面板）。

REQ-RPT-01代理报表源 邀请报表 A/C/D/M
  • 按统计周期切换（日/日区间/月/所有）+ 翻页；内部=返利、外部=返佣；「下级列表」真实下钻抽屉。
REQ-RPT-02昨日返佣等级源 User_RebateLv_Last
  • 五游戏列：每游戏「投注金额/返佣金额」双列分组表头；工具栏仅导出。

6.6 系统管理

REQ-SYS-01IP 黑名单（新增）源 BlackIp
  • 列表：IP（v4+v6）/封禁类型（多标签）/原因（字数计）/关联会员/操作人·时间/状态。
  • 批量导入：粘贴或上传 .csv/.xlsx（首列=IP），自动识别合法 IP、实时去重 ≤500 条，选类型+原因后确认。

8 · 非功能需求

在功能正确的基础上，本期对数据真实性、商户隔离、交互反馈与合规埋点提出统一约束，作为全站质量底线。

  • 数据真实性：所有数据/交互取自源（SitINR 源码/UAT），无源标「新」并先确认，不臆造。
  • 商户隔离：筛选区商户首位 + 表首商户列 + 商户视角隐藏商户列 + 切换即时重渲染。
  • 真实交互：导出真实下载 CSV、搜索真实过滤、排序真实重排、表单保存真实回写、删除真实移除，每步配 Toast。
  • 埋点合规：基础事件（激活/注册/登录/首充/付费）强制上报，作为归因采集依据。
  • 脱敏：手机/邮箱/卡号脱敏，按权限（viewphone/viewemail）展示完整值。
  • 反馈一致：Toast 3 秒自动消失；危险操作二次确认；弹窗点遮罩不关闭；校验失败标红+错误面板。

11 · 风险与待确认

以下为可能影响交付节奏或验收结论的开放问题，需在评审中明确责任方与结论。
