Ⓐ 前置知识 · 核心名词与关系（渠道ID / 渠道Code / 包ID / 包名）

4 名词
名词是什么存在哪（V1 源库）唯一性
渠道ID渠道的身份证：渠道表自增主键（如 26125），渠道管理建渠道时产生。tab_Channels.ChannelID全局唯一，系统生成不可改
渠道Code会员身上的来源印记：注册时命中哪个渠道，就把该渠道的标识写进会员记录，即渠道ID 的快照。tab_Users.ChannelCode（注释「渠道编号」）每个会员一个，值可重复（同渠道会员相同）
包ID一次打包产物的管理编号：打包记录主键，管下载 / 二维码 / 重新打包 / 删除，不参与归因。tab_APKPackageManagement.Id全局唯一
包名业务包名＝应用显示名（桌面图标名、商店可搜索的马甲包名）；另有技术包名 com.xxx.yyy（BundleId），同 App 多个马甲包技术包名必须不同。PackageTitle「APK包名」；新设计叫「应用名称」可重复（多渠道分包同名）

四组关系（类比：渠道ID=门牌号 · 渠道Code=快递单上抄的门牌号 · 包ID=快递单号 · 包名=箱子上的品牌名）

渠道ID ↔ 渠道Code
同一个值的两个角色：ID 是渠道表主键（管理用），Code 是注册时盖到会员身上的归因快照（统计用）。用快照保证渠道改名 / 关闭后历史归因不变。
包ID ↔ 包名
包ID 是「这一次打包」的唯一记录号；包名是「应用叫什么」。多渠道分包时：同一 App 打 10 个包＝同包名、10 个不同包ID。
包 ↔ 渠道
包必须挂一个渠道，打包时渠道code写入包体。V1 里 ChannelId 有唯一索引＝一渠道一包；新设计支持多渠道分包：一 App 投 N 渠道打 N 包。
全链路
渠道ID →（链接 ?ch= 或 写入包体）→ 会员·渠道Code（注册渠道）→ 渠道报表。包ID / 包名全程只管包，不进归因。

Ⓑ 前置知识 · 六种分发形态对照（安卓 / iOS / 壳包 / H5 / PWA）

6 形态
总原则：三个标识在六种形态中分工完全一致——渠道ID 是源头身份，渠道code 是随用户旅行的票根，包ID 是行李牌。形态间的区别只有一个：渠道code 怎么递到用户手上——H5 / PWA 贴在链接上，四种包形态缝进包体里。
分发形态包ID渠道code 如何到达用户埋点 / 设备标识
安卓 APK（原生）有（上传 .apk 的打包记录）打包时写入安装包，装完即归因GAID；Click + API 回传
iOS 原生（.ipa）有（上传 .ipa）写入包体；分发走「保存桌面」或「苹果商店」（需已封装域名）IDFA / IDFV，受 ATT 限制，重度依赖 CAPI
安卓壳包（WebView）有渠道code 写入壳体，壳打开推广域名 H5；更新内容不用重新发版壳内 H5 像素 + 服务端回传
iOS 壳包（WebView）有渠道code 写入壳体；商店上架需已封装域名壳内 H5 像素 + 回传
H5 链接无（无需打包）URL 参数 ?ch=渠道ID，浏览器直开H5 像素 + CAPI
PWA无（免打包，走 PWA 管理发布）带渠道ID 的 PWA 链接，添加到桌面时来源随之固化H5 像素 + CAPI + 推送召回
渠道ID 与渠道Code 六种形态全都有、作用一致；包ID 只有四种包形态才有——H5 / PWA 不经过打包管理，谈不上包ID。

Ⓒ 前置知识 · 归因统计流程（五步 + 流程图）

5 步骤
归因双轨流程图
步骤阶段发生什么标识动向
① 配置期一次性域名管理备域名 → 打包管理 / PWA 管理 → 渠道管理 → 埋点管理（渠道绑定 Pixel / Token）。四种包形态产生包ID、渠道code写入包体；渠道管理产生渠道ID，生成 ?ch= 链接 / 二维码。
② 投放期广告 / 分享广告平台（FB / TikTok / 谷歌 / Kwai）或代理分享发出链接、安装包、二维码。点击携带 clickid + UTM + 渠道码（+ 邀请码）。
③ 落地激活落地页 / 首启链接型从 URL 读渠道code；包型安装后首次启动从包体读渠道code，上报「激活 Activate」。渠道code 随用户到达系统。
④ 归因判定注册时刻 · 一次定终身主归因优先级唯一命中、命中即停：广告 UTM / clickid > 邀请 > 官方直推 > 自然流量（解析失败并入自然，原因记日志）；未命中渠道落默认自然流量兜底渠道。渠道Code＝渠道ID 快照写入「注册渠道」，注册即固化，关渠道 / 划拨均不回改。
⑤ 统计与回传持续对内按渠道Code 聚合注册 / 首充 / 付费 / ROI，三维归集渠道→商户→市场→集团；对外按 clickid CAPI 回传五个必传事件。渠道Code 进报表；包ID 只出现在打包管理的版本 / 下载量统计，与归因无关。
详细口径见 《推广分发配置说明》 与 《推广归因工作流》。

推广平台名称promoPlatform识别出的外部推广平台。带平台点击ID精确识别：Google（gclid）、Meta/Facebook（fbclid）、TikTok（ttclid）、Bing（msclkid）；经 utm_source 识别：Instagram、YouTube、Telegram、WhatsApp、X（Twitter）、Snapchat、Kwai、ShareChat、Line、Zalo；以上均未命中或无参数 → 其他。广告投放平台维度效果与对账；KOL/平台归集。多平台参数冲突按点击ID优先级判定；不可识别→其他；App 安装归因另行设计。

④ 代理数据组

9 字段
字段名词解释应用场景异常情况
一级代理rootAgentId该会员所在代理树的顶级（根）代理。总代业绩归集、分成顶层、大代理线监控。自身即根则显示自己/空；代理线超最大层级后新增不再挂树。
直接上级代理parentAgentId代理树中该会员的直接父节点（=邀请人）。一级返佣计算、直属关系展示。平台直客无直接上级；不提供转代，划拨只改经营归属不改代理树位置。
代理层级agentLevel当前深度 / 最大允许层级（如 3 / 10）。多级返佣分成层级、防无限级嵌套。达上限后下级不再建代理关系；层级数须与代理路径长度一致，否则告警。
代理路径agentPath根→本会员的完整代理 ID 链。超过 3 层时仅展示「一级 → … → 直接上级 → 本人」（中间层折叠），点击查看整条线全部代理信息。上下级关系核查、多级返佣溯源、闭环排查。≤3 层时全量展示不折叠；路径出现重复 ID→闭环异常；中间代理注销→以快照为准。
佣金模式commissionMode代理收益方式两类：返佣=投注流水返佣 / 返利=亏损分成返利。代理结算口径、不同代理线差异化激励。同线不同级可不同模式；模式变更只对变更后业绩生效，历史按原模式结算。
返佣等级rebateLevel会员自身的返佣等级/档位，决定其投注流水返佣比例（如 Lv3=0.5%）。返佣计算、等级化激励、与 VIP/活跃度联动调整。等级变更只对变更后流水生效，历史按原等级结算；无返佣资格时为 0 级/空。
是否给上级返佣rebateToUpline该会员产生的有效投注流水是否为其上级代理计提返佣。可配置开关，切换需二次确认。控制返佣链路；内部号/测试号可关闭不计佣。关闭后上级不再因其流水获佣，但代理树关系保留；与代理状态独立。
代理状态agentStatus代理资格状态（生效/冻结/注销），与用户账号状态独立。冻结作弊代理返佣但不影响其玩家身份；注销取消资格保留历史。账号启用但代理冻结/注销时，下级业绩不再计佣；状态变更留审计。

⑥ 登录信息组

5 字段
字段名词解释应用场景异常情况
登录端loginClient会员最近一次登录的客户端，枚举同注册端。活跃端分析、注册端与登录端一致性风控。登录端频繁跨端切换+异地→异常登录告警。
登录设备号/指纹loginDeviceId + loginFingerprint设备号与浏览器指纹合并展示：最近一次登录设备的稳定设备 ID（为后续原生包预留）与登录时采集的浏览器指纹，共同唯一标识登录设备。常用设备识别、异常设备登录监控、同设备多账号聚合。与注册设备号/指纹长期不一致→疑账号转手/接管；取不到时待原生包补采。
同设备登录数sameDeviceLoginCount与本会员同一设备（设备号/指纹）登录过的账号总数。共享设备/工作室识别、登录维度风控聚合。家庭共享设备可能误判，需结合行为研判。
同指纹登录数sameFingerprintLoginCount与本会员同浏览器指纹登录过的账号总数。关联账号识别、登录聚合风控。指纹可伪造/清除，须结合多维判定。
登录域名loginDomain会员最近一次登录进入的域名，可与注册域名不同（如注册走推广域名、登录走主站域名）。回流入口分析、主站/备用域名切换监控。跨商户域名进入应判异常并拦截；域名被封后登录走备用域名属正常切换。
