③七步工作流详解

1需求输入入口：用户口述 / PDF / 参照截图
  • 来源：用户直接提需求、产品 PDF（如《域名和渠道说明》）、参考截图、SIT/SitINR 现有页面。
  • 产品侧提需求可参照范本 产品→AI 提需求范本（8 要素 + 6 场景）。
  • 仔细看需求参考图中的字段先判定性质（配置项 ≠ 统计列），「不增加其他数据」要确认指代范围，避免砍错/补错。
2调研取证原则：真实环境优先，不编 mock
  • UAT/SIT 优先字段结构、枚举值、业务数据、接口形态一律先取真实环境（SitINR 线上 / SIT 租户后台 / 三仓源码），拿不到再退而求其次并说明。
  • SitINR 功能对照：SitINR 功能图谱（旧超管，/UserInfo/*）；源码逐页审计走 Ar_V1_Admin/PC.dianzan/Areas/Admin/Views/。
  • 新版参照：SIT 租户后台图谱（5 模块 24 页）。勿混用两图谱对应两个不同系统。
  • 列表类设计先看金标准：会员列表 = 全局列表模板（筛选/快捷时间/自定义列/合计行/分页跳页）。
3板块设计（含确认检查点）硬约束：先截图确认，再出正式 HTML
  • 一个板块一个板块推进：产出该板块 → 本地预览截图给用户 → 等确认 → 再产正式页面。不一次性做完整页。
  • 设计四原则：交互统一控件统一交互简洁小白友好（入口明显、文字引导、视觉反馈、重要操作二次确认）。
  • 层级体系：集团→市场→商户→域名→渠道→会员，商户是数据隔离边界，无品牌层。
  • 控件与名词全局一致；发现既有页面不一致，先问再做。
4注入实现（8200 member-app）统一入口：?open=hub，不再散建原型
  • 所有新交互注入 member-app（改 member-app/index.html 的 SPECS 数据驱动框架），共用 localhost:8200/?open=hub 一条预览链接；不再单独散建 prototypes/*.html 或新端口。
  • 新增一个模块 = ① SPECS 加条目（t 必须=菜单文案）② 菜单（build() 克隆注入 ADD / 删除走 HIDE）③ 工作台 T 数组加磁贴。
  • 两套视图认清楚：直接 hash 导航 = 真实 Vue 页（bundle 改不动）；点菜单/磁贴 = 注入 SPECS 覆盖层。给真实页「加列/加字段」只能做在 SPECS 覆盖层或 augment 增强。
  • 弹窗尺寸三级制：大图详情（基类 1480×88vh）/ 中表单（form 760×auto）/ 小确认（sm 440）。开关类操作一律二次确认。
  • 通用机制优先复用：freeze:N 列冻结、platTabs 平台页签、html: 图文页、FOPT 筛选真实选项、红列 [名,类型,1] 标新增。
5四处同步（增删功能点必做）缺一不可，详见 ⑤
  • ① 交互/下拉菜单（HIDE / ADD）② SPECS ③ 快捷工作台 T 磁贴 ④ 文档（saas-workplan 为首）。
  • 涉及计数口径（页面数/子分类数/合计）的所有文档一起改：workplan、PRD、功能说明书、new-content-list、naming 映射。
6实测验证改完必须在 8200 真实 DOM 核对
  • 改 index.html 注入层 → 普通 location.reload()（保留登录态）；改打包 bundle（如 index-*.js 菜单 iK）→ 必须 Cmd+Shift+R 硬刷新（会登出，登录让用户自己来）。
  • 删菜单项验证：DOM 里查被删 label 命中数 = 0；新增页面验证：菜单、磁贴、?open= 三个入口都可达（SPECS 存在 ≠ 可达）。
  • 控制台报错先看：注入框架块语法崩的标志 = __arShowPage 等全 undefined、点了没反应。
7交付 / 发布必附预览链接，不需要问
  • 任何修改完成后，回复末尾直接附本地预览链接：交互 → localhost:8200/?open=<route>；文档/原型 → localhost:8753/docs|prototypes/xxx.html。
  • 需要对外分享时走 GitHub Pages 标准流程（见 ⑥），发布后必须做内容比对校验，不能只看 HTTP 200。
  • 周报/日报/对外文案类输出由 Claude 负责起草。

⑦常见坑速查

场景坑正解
注入框架加 CSSCSS 是 JS 字符串拼接，塞裸换行 → SyntaxError → 整个框架崩（?open= 全失效）必须 + '.cls{...}' 逐行拼；崩了先看 console SyntaxError 行号
刷新方式Cmd+Shift+R 会登出 8200（登录不能代做）改注入层用普通 reload；只有改 bundle 才硬刷新，并让用户重新登录
删顶部下拉菜单项删 T 数组删不掉打包下拉项菜单项在打包 iK，走 HIDE；T 只管工作台磁贴
openModal 表单取值data-mok 先关弹窗再回调，onOk 里读不到 DOM所有字段 oninline 实时写 window store，onOk 纯读 store
z-index强改 Naive 下拉容器 z-index 会让主导航打不开层级定式：注入页 1990 < 下拉 2000+ < toast 3600 < 弹窗 3300（toast 高于弹窗）
并发会话同改一文件Edit 报 modified-since-read / 锚点 count=0先 grep 实际命名取现值；小补丁用 python assert+replace 原子写
列冻结测量容器未显示时 offsetLeft 全 0，冻结列全叠 left:0requestAnimationFrame + 零值重试再测量
8200 截图嵌文档无头 Chrome 直连被登录页拦；JS 原文 return 被安全过滤已登录标签导航 → 抽 DOM+CSS → Blob 下载 → file:// 无头截图 → PIL 裁白边
验证入口可达性SPECS 有条目 ≠ 用户能点到核对「菜单 + 磁贴」两层入口；冒烟别 JS 狂切路由（会卡死渲染线程）
