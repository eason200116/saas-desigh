推广分发 → 获客归因 · 端到端工作流

把「域名 → 打包 → 渠道 → 埋点」的配置侧，与「投放 → 获客 → 归因 → 归集/回传 → ROI」的归因侧串成一条闭环工作流。每一步标注 负责角色 / 输入来源 / 关键操作 / 交付产出 / 对应后台页，并贯通到会员的归因字段与代理返佣。基于现有原型与文档归纳。

§4 归因判定逻辑

主归因优先级（优先级唯一、命中即停、就高不就低）
  • 广告 UTM / clickid → 广告投放
  • 有效邀请链接 / 邀请码 → 邀请来源（同时建代理树）
  • 官方推广链接 → 官方直推
  • 自然访问（无来源参数）→ 自然流量
  • 全部无法识别 → 自然流量（并入自然，失败原因记日志）
邀请链接与 UTM 并存 → 判广告投放，邀请码留辅证、仍挂代理树返佣并标「裂变获客」。原始来源注册即固定，划拨 / 撤代 / 关渠道均不改写。
邀请来源再分三类 invite_type
类型值来源
正常邀请normal个人邀请码 / 链接
转盘活动邀请wheel邀请转盘裂变
邀请任务task邀请任务活动
三类都进代理树、都归上级代理；活动邀请（转盘 / 任务）额外触发对应活动奖励并记 invite_activity_id。详见 归因判定流程图。

必传基础事件强制上报；首充 / 付费为核心优化事件，回传给平台用于广告优化与 ROAS。

注册 Register注册成功CAPI注册转化、CPA
登录 Login登录CAPI活跃 / 留存信号

埋点管理按投放平台（Facebook / TikTok / Kwai / 谷歌）动态配置，事件名按平台映射；配置后用测试回传验证 Click / API 链路是否打通（Facebook-API 5 步流程）。

§6 数据归集与代理返佣

三维归集
渠道 → 商户 → 市场 → 集团
  • 每个新会员的原始来源逐级归集，形成渠道 / 商户 / 市场 / 集团各层的获客与转化报表
  • 原始来源固定，后续划拨 / 撤代 / 关渠道不改写历史归因
代理返佣
  • 邀请来源（normal / wheel / task）注册即挂到上级代理树，佣金按代理模式结算
  • 活动邀请额外触发对应活动奖励（转盘奖励 / 任务奖励）并记 invite_activity_id
  • 例：A 邀请 B → B 归 A；A 分享邀请转盘拉来 C → C 归 A + 发转盘奖励
